# 世界立繪規格（地圖 Sprite）

- 版本: v3.0（2026-08-14；定案 1280 Design Reference → 64px Pixel Art Reference → 64px Native Seed 三層素材）
- 狀態: 現行正式規格
- 適用: overworld 主角、NPC、事件人型與會直接出現在地圖上的魔物
- 流程唯一來源: [世界立繪流程.md](../pipeline/世界立繪流程.md)
- Prompt 組裝: [role_world.md](../pipeline/prompt/role_world.md)、[enemies_world.md](../pipeline/prompt/enemies_world.md)

> **權威邊界**：本檔是 world sprite 的尺寸、命名、視覺與驗收數值唯一來源；流程文件只定義 Gate 與操作順序，prompt／skill／TASK 只能引用，不得再內嵌另一套數值。角色立繪與戰鬥立繪可依設定身高正規化；world sprite 不依 cm 縮放。

---

## 一、三層素材與真相源

| 層級 | 正式名稱 | 規格 | 用途／權威性 |
|---|---|---|---|
| D1 | High-res World Design Reference | `1280×1280px`、非 Pixel Art、透明 RGBA | 五官、髮型、服裝、配件、材質、色票、方向與不對稱設計的細節真相源；不是 runtime 尺寸真相源 |
| D2 | Pixel Art Reference | `64×64px`、原生 Pixel Art 候選 | 將 D1 轉譯成 world 尺度，確認角色辨識、輪廓、像素語言與細節取捨；仍可修改，不是 strip frame 0 |
| D3 | Approved Native Seed | `64×64px`、清稿後正式 Pixel Art | 該方向所有 strip 的 production 真相源；對應 strip frame 0 必須逐像素完全一致 |

### D1：High-res World Design Reference

- 固定 `1280×1280px`（`64×20`），採精細、非 Pixel Art 的日系 JRPG 角色素材。
- 一般人型共用同一套 world Q 版頭身、站姿尺度與鏡頭角度；不按角色設定的 158／165／178 cm 拉高矮。
- 高解析的用途是看清細節，不是縮小來源。D1 禁止經 resize、quantization、色彩取樣或銳化直接成為 D2／D3。
- `Down` 是主外觀 reference；下列情況必須另補 `Side`／`Up` 方向 reference 或同等清楚的設計標註：背包、披風背面、側馬尾、單肩裝備、武器掛側、傷痕、胸針、腰包等正面看不到或左右不對稱的特徵。
- 每名角色建立「64px 身份特徵表」：必留、可簡化、必捨棄、禁止新增。不得企圖把 D1 所有細紋塞入 64px。

正式命名：

```text
world_design_ref_down_1280_{raw,alpha}.png
world_design_ref_side_1280_{raw,alpha}.png   # 需要時
world_design_ref_up_1280_{raw,alpha}.png     # 需要時
```

### D2：Pixel Art Reference

- 必須在 `64×64` 原生 grid 上重新 Pixel Art 化；可用精確整數倍 logical grid authoring，但每個 logical pixel 必須是完全均勻、對齊的 `N×N` block，才能無損 collapse 回 64px。
- D2 是 D1 的 Pixel Art 版本，不是 D1 的自動縮圖。舊 `*_native64_ref.png`／`make_native64_ref.py` 產物僅為歷史 layout diagnostic，不得當 D2、D3 或 strip reference。
- D2 可為候選，允許調整眼睛 pixel、髮際、輪廓、配色層級與細節取捨；通過原生 `1×`、放大逐像素與實景三層驗收後，才進 D3 清稿。

正式命名：`seed_<dir>_pixel_ref_64.png`。

### D3：Approved Native Seed

- D3 只能由同尺寸 D2 清稿、校色、去殘色與 anchor 校正得到；禁止再次從 D1 縮圖或重畫另一張近似圖冒充。
- `Down` D3 先凍結為角色的主 world seed；`Left／Right／Up` 依 D1 方向資料與 Down D3 製作，各方向也要有自己的 D3，作為該方向 walk strip frame 0。
- D3 一旦核可即版本凍結。若 D1 外觀改版，所有下游 D2、D3、strip 都必須標示待重驗，不可默認仍相容。

正式命名：`seed_<dir>_native_64.png`。

## 二、標準人型尺寸與體型

- Cell：固定 `64×64px`；runtime scale 固定 `1.0`。
- 一般人型完整可見 bbox：高度 `58..64px`、寬度 `28..40px`。
- 建議常態高度 `60..62px`；使用完整 `64px` 高時，頭頂會到 `y=0`、腳底到 `y=63`，必須額外證明所有動畫幀都不裁切。
- 尺寸量測包含頭髮、馬尾、兜帽、披風與衣服外輪廓；不包含透明留白、場景影子，也不以獨立長武器／法杖尖端決定一般人型 bbox。
- 最低接地 opaque pixel 固定在 `y=63`；水平 root 為 cell bottom-center，概念座標 `(32,64)`，雙腳視覺中心須穩定落在 cell 中央。
- world sprite 不呈現一般人型之間的實際 cm 差。年齡、體格與角色差異改由肩寬、頭身、輪廓、姿態、服裝量體表現。
- 小孩、矮人、巨漢、非人型與大型魔物是例外體型：W0 先按場景可讀性鎖定 cell 與 bbox，不從設定 cm 自動換算，也不得套用一般人型範圍硬拉伸。
- 大型角色以 `32px` 為 cell 增量，例如四足大型熊 `96×64px`、正面直立熊 `64×96px`。

### 武器、持物與換裝

- 一般 world idle 預設不採戰鬥舉武器姿勢；長武器、法杖預設收起或不顯示。
- 任務要求持物時，W0 必須明訂持物是否計入 cell；超出 64px 時用較大 cell 或獨立圖層，不得把整個角色縮小遷就武器。
- 裝備更換預設不改 world sprite；使用 canonical travel outfit。只有重要劇情造型另建完整 variant，狀態光效優先使用 shader／獨立 FX，避免服裝×裝備×狀態組合爆炸。

## 三、方向、鏡像與動畫單位

### 正式名詞

- **Native Seed**：單張 64×64 D3，不稱為 strip。
- **Walk Strip**：單一方向 9 格，標準人型正式 Alpha 尺寸 `576×64px`。
- **Idle Animation Strip**：未來若加入眨眼／呼吸，另作 `N×64px`；不得混入 Walk Strip 的 `1..8`。
- **Runtime frames**：由正式 strip 切成每幀一張透明 PNG。

### 正式 walk

- 方向固定 `Down / Left / Right / Up`，對應 `world_scene.gd` 的 `Idle<Dir>`／`Walk<Dir>`。
- 每方向 9 幀：`0=該方向 Native Seed`，`1..8=walk cycle`；runtime 只循環 `1..8`，Idle 不插入 walk。
- 四個方向分開製作與驗收，不直接生成 `9×4` sheet。
- 同一 strip 必須一次完成，所有格共用 cell、global scale、Pixel Art 密度、腳底線與 bottom-center root；禁止逐幀 fit-to-cell 或逐幀各自生成後拼成正式動畫。

| 幀 | 步態相位 |
|---|---|
| 1 | 左腳接觸：左腳踏出、右腳在後 |
| 2 | 左腳承重：左腳穩定、右腳開始離地 |
| 3 | 左腳 passing：右腳向前通過、雙腳距離收近 |
| 4 | 左腳 recovery：左腳向後收、準備切換右腳 |
| 5 | 右腳接觸：右腳踏出、左腳在後 |
| 6 | 右腳承重：右腳穩定、左腳開始離地 |
| 7 | 右腳 passing：左腳向前通過、雙腳距離收近 |
| 8 | 右腳 recovery：右腳向後收，可無縫接回 frame 1 |

### 鏡像規則

- 每個角色在 metadata 記錄 `mirror_safe`。只要有慣用手、側馬尾、疤痕、單肩披風、胸針、腰包、武器掛側或不對稱護具，即為 `false`。
- `mirror_safe=false` 時，Left／Right 必須各自製作；不得鏡像後把不對稱特徵留在錯側。
- 即使 `mirror_safe=true`，鏡像版仍須獨立通過方向、光向、近／遠腿與實景 Gate。

### 三幀簡易版／事件版

- 簡易人型只供 prototype 或明確核可的低成本 NPC：`Idle / Step L / Step R`；不能冒充正式八相位 walk。
- `Step L／Step R` 必須交換鞋尖落點、膝蓋重疊、褲管明暗、髖部遮擋與承重腳；不得只平移、鏡像或擺衣角。
- 事件 actor／魔物可依劇情使用三幀 idle、呼吸或踏步 strip，命名 `Field`、`Upright` 等語意姿態。

## 四、Pixel Art 視覺語言

- 高品質約二頭身 world Pixel Art；先保證原生 `1×` 的方向、身份、服裝大色塊與腳步可讀，再追求放大細節。
- 一般人型使用相近的頭部視覺量、手腳最小厚度、像素群密度與明暗層級；不得因 D1 細節較多就讓某一角色特別碎或銳利。
- 描邊以 1px 深棕／深灰棕為主；避免純黑粗邊、孤立噪點與戰鬥圖式高反差金屬高光。
- 頂光、中低飽和、中對比、柔和體積陰影；目標地圖截圖與一名已核可 world 角色是色調／密度比較基準。
- D1 身份特徵表依序取捨：輪廓與髮型 ＞ 主服裝色塊／披風 ＞ 臉部辨識 pixel ＞ 代表配件 ＞ 刺繡、鈕扣與材質細紋。
- 不得新增 D1／角色設定沒有的腰包、飾帶、金屬件、髮飾或花紋。
- 圖內不得包含地面、烘入影子、文字、UI、格線、發光、外框或浮水印。

## 五、Alpha、色彩與接地影子

- D3、Alpha strip 與 runtime frames 使用 RGBA；正式 Pixel Art 的輪廓 Alpha 原則上只能是 `0` 或 `255`。半透明只供明確指定的 FX，不用於一般角色抗鋸齒邊。
- 可見鍵色殘點必須為 `0`；完全透明 pixel 的 RGB 必須正規化為 `(0,0,0)`。
- 接地影子由 runtime 獨立生成，禁止烘進 sprite。
- 標準影子 RGB `(58,52,44)`；中心 Alpha `127/255`、邊緣最低 Alpha `13/255`，依 `(1-distance)^1.35` 漸淡。
- `64px` cell 影子垂直範圍 `y=57..63`，寬度依角色可見寬度約 `0.95×`，一般人型限制 `28..40px`；實景確認不偏心、不黑成實心斑。

## 六、Runtime 與取樣

- Runtime：`assets/char/<id>_<Dir>_0..8.png`；標準人型每張 `64×64px`、scale `1.0`。
- 像素素材 import 使用 Nearest、lossless、關閉 mipmaps；不得沿用全域 Linear。
- Sprite root／腳點與碰撞、YSort 分離；替換圖片不得改變角色碰撞與世界座標語意。
- 實機必驗 `1280×720` 設計基準與 `1920×1080` 輸出，包含專案實際 `1.8×` camera zoom、移動中 pixel 寬度、subpixel shimmer、方向切換與 follower 對齊。
- 長期不得保留 per-character runtime scale 特例；舊 96px＋`2/3` 素材只屬遷移期。

## 七、版本與失效管理

每個角色／variant 在來源目錄保存 `world_art_meta.json`，至少包含：

```json
{
  "character_id": "<id>",
  "variant": "travel",
  "design_ref_version": 1,
  "pixel_ref_version": 1,
  "native_seed_version": 1,
  "strip_source_seed_version": 1,
  "mirror_safe": false
}
```

- D1 變更五官、服裝、配件、方向或色票時，D2／D3／strip 標記待重驗。
- D2 只改像素取捨時，D3／strip 標記待重驗。
- D3 改版後，所有引用舊 `native_seed_version` 的 strip 必須重驗 frame 0 與實景；不可只靠資料夾名 `final` 判斷相容。
