# 遮擋物件資產架構

- 狀態：定案
- 建立日期：2026-07-26
- 適用：手繪畫面地圖的非互動高物件（城鎮建築、樹、井、路燈、柵欄端柱、地標）

## 目標

將地圖拆成滿版 `Ground` 背景與可重用的透明遮擋物件。遮擋由 Godot `YSort` 處理；碰撞由 terrain 與 map 的 `props` footprint 合併生成，兩者各自維持唯一真相。

## 職責分離

| 場景節點 | 內容 | 碰撞／遮擋責任 |
|---|---|---|
| `Background`＋`Ground` | 滿版手繪底圖：草地、道路、地面陰影 | terrain 定義地表碰撞 |
| `GroundProps`（不參與 YSort）| `layer: "ground"` 的平貼素材：農作列、低矮植被 | **不遮玩家**（不依 y 排序）；碰撞另由 `walkable` 決定 |
| `YSort`（高物件＋Player）| 建築、樹、井、路燈等透明 PNG | 以 bottom-center anchor 和角色自然排序遮擋；`props` footprint 定義其碰撞 |
| gameplay 節點 | NPC、寶箱、門、採集點與 Trigger | 依互動邏輯配置 |

物件的 footprint 由 `map-def.json` 同一筆 `props` 記錄提供給場景與碰撞生成器；不可在場景另外手刷同一份碰撞。

**`walkable` 旗標（2026-07-29 新增）**：`meta.json` 標 `"walkable": true` 的物件**不生碰撞**，玩家可踩過去。`blueprint_to_paths.gd` 只看這一個旗標（讀不到 meta 時保守當作會擋）。目前標記者與理由：

| id | 理由 |
|---|---|
| `stairs_stone_wide_a` | 石階本體就是通路；不標的話會把礦坑唯一通道封死 |
| `crop_field_rows_a` | 低矮農作、走得過去 |
| `fence_wood_tile_gate_v_open_a`／`_left_a` | 開著的門；不標的話圍起來的農田進不去 |

**擺放層要跟著分**：`layer: "ground"` 的物件（農田）放在 `YSort` **之外**、`Background` 之後的 `GroundProps` 節點——放進 `YSort` 會依 y 排序遮住站在上面的玩家。其餘高物件一律進 `YSort`，與玩家同一排序系統。

**素材層級規格＝碰撞的單一真相（2026-08-19）**：`meta.json` 的 `footprint`／`walkable`／`layer` 是**這個素材**的規格，不是某次擺放的屬性。map-def 不再逐筆複製 footprint；生成器一律回頭讀 meta.json，所以**同一物件在任何地圖都是同一套碰撞，校正一次即全域複用**。校正流程見 `TASKS/22`。

**旗標怎麼被讀到（2026-08-19 實作）**：`walkable` 與 `layer` **兩個旗標都直接讀素材庫 `meta.json`**，不寫進 `map-def.json`——`blueprint_to_paths.gd` 的 `_prop_is_walkable()` 決定生不生碰撞，`build_scenes.gd` 的 `_prop_layer()` 決定掛 `GroundProps` 還是 `YSort`（map-def 該筆若有 `layer` 欄則優先，供個別例外覆寫）。好處是**改素材旗標不必回 map editor 存檔**；map editor 只負責顯示（不擋人＝綠虛框、地面層加註），不複製旗標。

## 素材分類與命名

來源目錄：`assets-source/props/world/<type>/<footprint>/<id>/`；整合目錄：`godot-project/assets/props/world/<type>/<footprint>/<id>.png`。

| type（中文） | 用途 | footprint 例子 |
|---|---|---|
| `architecture`（建築） | 民宅、商店、旅店、教堂、公會、鐵匠鋪 | `2x1`、`3x2`、`5x2`、`6x2` |
| `nature`（自然物） | 樹、灌木、岩石群 | `1x1`、`4x4` |
| `street`（街道設施） | 路燈、井、攤車 | `1x1`、`2x2` |
| `structure`（結構物） | 柵欄、柱子、短牆、門架 | `1x1`、`2x1`、`4x3` |
| `landmark`（地標） | 礦坑入口、城門、祭壇 | `4x3`、`6x6` |

`footprint` 是玩法／配置尺寸，不是 PNG 畫布尺寸。每個 `meta.json` 必須記錄實際 `canvas_px`、`footprint`、`anchor: bottom_center` 與 `occludes_player: true`。

**footprint ＝ 只有「腳下擋人」的那塊，通常遠小於視覺**（2026-07-28 定案）：建築取底部 2 格深、樹只取樹幹 1×1，屋簷、樹冠、招牌一律不算。視覺尺寸由 `canvas_px` 原生決定（例：`tree_oak_round_a` 1×1 footprint 配 192×192 畫布＝視覺 6 格寬），編輯器與 `build_scenes.gd` 都以 footprint 底邊中央為 anchor 貼圖，所以**改 footprint 會連帶移動貼圖位置**——改動時必須同步補償 `map-def.json` 已放置物件的 `cell`（高度變化補 y、寬度變化補 x，半格無法整格對齊時統一往右取整）。

**例外：可拼接素材與地面層（`tile_set`／`layer: ground`）的 `canvas_px` 必須等於 footprint×32**，否則相鄰格會互相重疊、蓋到不該蓋的地格；`fence_wood_tile_*` 為 1×1＝32×32、`crop_field_rows_a` 為 4×4＝128×128（2026-07-28 由 96×96／256×256 等比縮正）。非拼接的獨立高物件不受此限，畫布可遠大於 footprint。

**入口規則**：有門、洞口或可進入落點的高物件，入口必須直接接觸物件的**底邊**，但不要求水平置中；入口的實際落點由地圖的 `entrances` 與 gameplay 節點決定。`bottom_center` 僅是 Sprite 在 `YSort` 的排序 anchor，和入口位置無關。

**建築朝向規則**：`architecture` 與可進入的 `structure`／`landmark`，正面必須平行於畫布底邊，禁止側向 45° 構圖或讓建築斜跨地格。只允許屋頂、立面與高度的 3/4 俯視表現；入口得以直接對齊底邊道路與 32px 格。

## 製作流程

1. 在 map editor 的 `props` 配置物件 id、座標與 footprint；它會同時餵場景與碰撞生成。
2. 先產三張 design anchor 候選，核可後用 anchor 產出透明物件；流程沿用 [`workflow.md`](workflow.md) 的 preview、驗收與素材來源規則。
3. 重繪滿版 `Ground` 時不得烘入任何高物件；可保留物件底部的低矮地面陰影。
   - **M1 `town`（芳蕾鎮 v2，原 `floret_v2`，2026-07-29 已併回 `town` 並刪除 v2）已驗收例外**：芳蕾鎮背景直接繪入 `^` 山壁、`f` 密林與北側礦山入口，礦坑入口不再於該圖的 `props` 重複擺放；獨立樹木 prop 仍可用於草地點綴與森林層次，碰撞仍以 terrain 與保留的 prop footprint 為準。
4. 場景由 `build_scenes.gd` 生成：高物件以 bottom-center anchor 放進 `YSort`（角色同一個排序系統）、`layer: "ground"` 的放進 `GroundProps`。
5. 只有 John 驗收後才能複製至 Godot assets、更新 `CREDITS_素材授權.md`，並執行 Godot headless 檢查。

`crop_field_rows_a` 是低矮物件，可置於 `Ground`；其餘列出的物件均為透明 PNG，放入 `WorldProps` 的 `YSort`。北方礦山入口、建築與石階的門口／落點仍由 `entrances` 與 gameplay 節點管理，不能烘死在物件素材內。

`fence_wood_tile_set_a` 由已驗收的 3×3 母圖精準切出，所有成員皆為 `1x1`；開門圖只表現視覺狀態，實際通行與碰撞仍由地圖的 `props`／terrain 資料配置。

**拼接組是「每條邊各有專屬成員」，不能互換**（2026-07-28 釘死）：母圖畫的是一個封閉矩形，切格後軌條在格內的偏移量隨邊而異，用錯邊就會出現 7–15px 錯位。以 32×32 格內的不透明像素範圍表示：

| 邊 | 軌條位置 | 成員 |
|---|---|---|
| 上邊 | y 7–17 | `corner_tl`／`straight_h`／`gate_h_closed_top`／`corner_tr` |
| 左邊 | x 5–11 | `straight_v`、`gate_v_open_left` |
| 右邊 | x 20–26 | `straight_v_right`、`gate_v_open` |
| 下邊 | y 14–24 | `straight_h_bottom`、`gate_h_closed`、`corner_bl`／`corner_br` 的橫向端 |

門片狀態受母圖限制：橫向只有**關門**、縱向只有**開門**（上／下邊得到關門，左／右邊得到開門）。要橫向開門或縱向關門必須另外產圖，不能靠平移。

補新成員時**用純平移、不要用旋轉或鏡像**：需要的位移量剛好是整數（右邊＝左邊右移 15px、下邊＝上邊下移 7px），平移能保留原本的光影方向與柱子排列；旋轉 180° 雖然邊緣數值也對得上，但會把圖上下翻，接縫處會出現錯階。
