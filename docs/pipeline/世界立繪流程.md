## 二、核心製作方式

### 1. Seed-first

先選一張角色真正會出現的地圖截圖，搭配角色立繪／設定產一張 `Down Idle`。候選必須同時提供：

- 放大靜態圖：確認人物辨識度、像素密度、輪廓與解剖。
- runtime 原生尺寸場景合成：確認縮小後仍可讀，且色盤、對比、頂光、體積與附近角色一致。
- bottom-center 腳點：不得以畫布中心或頭頂當 anchor。

John 核可後，這張就是該角色的 world seed；後續 strip 必須沿用它的造型、色盤、比例、視角與腳底位置。

### 2. 一次產完整 strip

- 產圖單位是**單一方向＋單一動作家族的完整 horizontal strip**，不是逐幀各自產圖。
- 同一 strip 的所有幀必須在同一次生成中完成，以維持臉、服裝、配件、體型、光源與 Pixel Art 密度一致。
- 不直接要求模型生成 `9×4` 全方向 sheet；每個方向分開產 strip，逐方向通過 Gate 後才切圖與組裝。
- 若模型無法完全重現已核可 seed，後製時以核可 seed 鎖定 frame 0，但不得用獨立生成的不同畫風幀拼成動畫。

### 3. 幀組

| 類型 | 每方向產圖內容 | runtime |
|---|---|---|
| 簡易 idle／walk 驗證 | `Idle / Step L / Step R` 三幀 strip | `0=Idle`；`1..8=L/R` 交替 |
| 正式 walk | `Idle`＋8 個完整步態相位 | `0=Idle`；`1..8` 循環 |
| 事件角色／魔物 | 依任務需要的 3 幀 idle、呼吸或踏步 strip | 依事件腳本播放 |

`Step L`／`Step R` 必須真的交換接觸腳、膝蓋重疊、髖部遮擋與鞋底落點；只移動手、衣角或整體上下平移不算換步。

### 4. 尺寸由場景決定

- 標準人型先以 `64×64` cell 製作。
- 大型角色可按需求在橫向或縱向增加 `32px`，例如四足熊 `96×64`、正面直立熊 `64×96`。
- 尺寸選擇以實際場景中的體積與辨識度為準，不以透明背景上的「精緻度」決定。
- strip 各格 cell、角色全域縮放、腳底線與 bottom-center anchor 必須相同；禁止逐幀自動 fit-to-cell。

## 三、Prompt 與輸出合約

正式 prompt 由 [role_world.md](prompt/role_world.md) 或 [enemies_world.md](prompt/enemies_world.md) 組裝，至少寫明：

- `one horizontal sprite strip`、精確幀數、由左至右的每格內容。
- 所有格等寬、單一角色、同一比例／色盤／光源／視角／Pixel Art 密度。
- 腳底在同一基準線、bottom-center root-lock、每格有安全留白。
- 滿版單一鍵色背景；無投影、無地面、無文字、無格線、無 UI。
- 以核可 seed 為外觀真相源；目標地圖只作色調與原生尺寸驗收 reference。

來源檔建議命名：

```text
<direction>_<action>_strip_raw.png
<direction>_<action>_strip_alpha.png
<direction>_<action>_<frame>.png
<direction>_<action>_review.png
```

簡易三幀可用 `down_threeframe_*`；事件魔物可用 `field_threeframe_*`、`upright_threeframe_*`。

## 四、去背、切圖與正規化

1. W3 raw strip 通過後才去背；鍵色規則同 [50_去背螢光底.md](battle_art/prompts/sections/50_去背螢光底.md)。
2. 依固定 cell 切圖，禁止因各幀 bbox 不同而使用不同縮放。
3. 對整條 strip 套用**單一 global scale**，再將每幀放到共同畫布的 bottom-center anchor。
4. 若 seed 已核可，frame 0 必須保持其實際像素尺寸與腳點；其餘幀向它對齊。
5. 每次 resize、quantization、indexed／RGBA 轉換後，逐格檢查最終尺寸：
   - `alpha > 0` 的可見 pixel 不得殘留鍵色，數量必須為 `0`。
   - `alpha = 0` 的 pixel，RGB 正規化為 `(0,0,0)`。
   - 在中性淺灰與高對比底放大至少 6× 檢查輪廓。
6. 像素 sprite 的 Godot `.import` 使用 **Nearest**。

## 五、場景與影子驗收

每組 strip 必須產一張實際地圖合成，角色以 runtime 原生尺寸顯示；至少同框放入一名已核可角色作比例基準。檢查：

- 縮小後方向、服裝輪廓、臉／頭部與腳步仍讀得出來。
- 色調、飽和度、對比、描邊、頂光與地圖一致，不像縮小的戰鬥立繪。
- 主體沒有被過度銳化或細節糊成噪點。
- 腳底正確落地；四足、直立或大型角色的體積符合任務情境。
- 接地影子由場景獨立生成，**不得烘進 PNG**。標準設定見規格文件；大型角色依可見體積放寬橢圓尺寸。

若需要 GIF，使用 runtime 幀序與速度產生；仍必須同時保留靜態逐幀與實景合成圖。

## 六、整合與命名

- 標準角色：`godot-project/assets/char/<id>_<Dir>_0..8.png`。
- 事件 actor 可用語意方向／姿態：`<id>_Field_0..2.png`、`<id>_Upright_0..2.png`。
- `world_scene.gd` 組成 `Walk<Dir>`／`Idle<Dir>`；事件 actor 由對應場景腳本組幀。
- 核可後才把 raw、alpha 與最終 frames 留存到 `assets-source/role/<kind>/<id>/overworld_<variant>_final/`。
- 同步更新 `CREDITS_素材授權.md`，Reimport，並執行對應 headless／場景 smoke test。
