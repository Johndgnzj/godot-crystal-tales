# 世界 Sprite Strip 產線

- 版本: v3.4（2026-08-14；W2 加入 D2 logical-grid、outline 與 block 驗證）
- 適用: 主角、NPC、事件人型、四足／直立魔物等會直接出現在世界地圖上的 sprite
- 規格唯一來源: [世界立繪規格.md](../design/世界立繪規格.md)
- 驗收: 一律遵守 `CLAUDE.md` 兩階段產圖驗收；John 核可前不得整合 runtime

> **不重複規格**：尺寸、bbox、命名、風格、Alpha、影子與 runtime 數值只以規格文件為準。本檔只定義製作順序、Gate 交付物與退回條件；prompt、skill、TASK 不得另寫一套相衝突數值。

## 二、W0：需求與變體鎖定

開始產圖前記錄：

1. 角色 id、來源設定與 canonical world variant；一般換裝不反映 world sprite，重要劇情造型另開 variant。
2. 一般人型或例外體型；例外按場景可讀性定 cell，不依設定 cm 換算。
3. 目標地圖截圖與至少一名已核可 world 角色比較圖。
4. 需要的方向、正式九幀 walk／簡易 prototype／事件姿態，以及是否另作 Idle Animation Strip。
5. 武器／持物是否顯示、是否需較大 cell 或獨立圖層。
6. `mirror_safe`；正面看不到或左右不對稱的設計資料是否齊全。
7. 身份特徵表四欄：必留／可簡化／必捨棄／禁止新增。

缺少任何會改變角色輪廓、方向或 variant 的決定時停在 W0，不能讓模型自行補完。

## 三、W1：D1 High-res World Design Reference

### 製作

- 依規格 §一建立 D1 非 Pixel Art、透明的精緻二頭身 world 角色 reference；D1 與未來 D2 共用頭身與輪廓量體，不得先產一般角色立繪比例再縮小。
- `Down` 是主 reference；有背面／側面／不對稱資訊時另補對應 reference，不能靠文字中的「同角色」期待模型猜對。
- D1 只鎖身份與細節，不按 cm 排隊，也不作 runtime 場景比例判定。

### 驗收

- 對照角色設定與正式角色立繪逐項核對五官、髮型、服裝層、配件、色票、材質與不對稱側。
- 確認一般人型共用同一套 world Q 版頭身與站姿尺度；不因畫布留白誤判身高。
- 身份特徵表必須能回答「縮到 64px 時先留什麼、必須丟什麼」。
- 通過後凍結 `design_ref_version`；若日後改版，下游全部標記待重驗。

## 四、W2：D2 Pixel Art Reference

### 製作

- 以 D1 與身份特徵表為外觀來源，在規格指定的 D2 logical grid 製作獨立 Pixel Art Reference；保留相同二頭身比例、姿勢、輪廓量體與方向。
- 禁止使用 Nearest、BOX、Lanczos、quantization、先縮再補眼睛或自動取代表色，把 D1 自動轉成 D2。產圖候選的 grid 正規化只作用於已獨立轉譯的 D2 raw，且 W2 必須以正規化後圖像驗收。
- D2 用來鎖定中等細節 Pixel Art、outline 與省略規則；細節必須比低解析 world 樣張多、比高解析像素插畫少，也不套用 D3 的 cell、bbox、腳底線或 validator。
- 現存 `*_native64_ref.png` 是舊自動縮圖 layout diagnostic，不進 W2 Gate。

### 必交預覽

1. D1 與 D2 等比並排，標註二頭身輪廓、身份特徵、服裝層與不對稱設計的對應。
2. D2 logical `1×`、交付尺寸與局部細節，顯示 grid block、outline、受控色階、頂光、主要材質與省略方式；附 block-uniformity 與 Alpha 驗證結果。
3. 以低細節樣張為下限、過細像素插畫樣張為上限，將候選 D2 置中並排；確認它比下限多一級可讀結構，又沒有上限的逐髮絲、完整刺繡與大量微小 cluster。
4. 若為不對稱角色，附上對應方向資料，確認 D2 沒有轉移或自行新增配件。

### 驗收

- 依規格 §八 D2 清單驗 canvas、logical grid、block uniformity、binary Alpha、比例、身份、outline、像素群、色階、頂光、材質、省略規則與三點密度校準。
- D2 不進 runtime 實景、不檢查角色 cm 排序，也不以縮到 64px 後的清晰度作為 W2 通過條件。
- D2 仍是候選；眼睛、髮際、輪廓、色階、像素密度與細節層級可在本 Gate 反覆修改。

## 五、W3：D3 Approved Native Seed

1. 同時附上核可 D1、D2、身份特徵表、舊 world 風格比較角色與目標地圖，在規格指定的原生 grid 重新設計 D3。
2. 禁止縮小、collapse、quantize 或銳化 D1／D2；D3 保留 D1 身份與 D2 Pixel Art 語言，但必須為原生尺度另行取捨。
3. 先完成 `Down` D3；通過後再用 Down D3＋D1／D2 方向資料製作 Left／Right／Up D3。
4. 每個方向 D3 都要各自通過原生 1×、8×、核可角色同框與目標地圖合成。
5. D3 核可後凍結 `native_seed_version`，成為該方向 strip frame 0 唯一真相源。

標準人型先跑結構驗證：

```bash
python3 tools/validate_world_strip.py \
  --native-seed assets-source/role/<kind>/<id>/<variant>/seed_down_native_64.png
```

例外體型必須把 W0 鎖定的 bbox／cell 明列為 validator 參數，不得因 validator 預設為一般人型就硬縮角色。

## 六、W4：單方向完整 Raw Strip

- 一次只製作一個方向＋一個動作家族；正式人型 Walk Strip 是 frame `0..8`，不直接生成四方向 `9×4` sheet。
- 實際附上該方向 D3 圖，不得只給檔名或文字描述；要求 frame 0 保留 D3 身份、輪廓與 anchor。
- strip 必須在原生 logical grid 或可驗證的精確整數倍 grid 完成；禁止把高解析人物逐格縮小、逐幀獨立生成後拼接或用程式平移肢體當正式成品。
- raw 使用滿版單一鍵色、無格線、標籤、地面、影子、文字或 UI；每格有足夠 padding 且角色不裁切。
- 交付 raw strip、等格切片與幀號 montage；先驗身份、方向、解剖、尺寸、腳底與循環，再去背。

正式 walk 步態與鏡像規則直接引用規格 §三，不在 prompt 或本流程維護第二份相位表。

## 七、W5：Alpha、切幀與結構驗證

1. W4 通過後才去背；透明區 RGB 歸零，正式角色 Alpha 只能 `0/255`。
2. 依固定 cell 切幀；全 strip 共用 global scale、腳底線與 bottom-center root，不逐幀 fit-to-cell。
3. frame 0 必須鎖回該方向 D3，並通過逐像素一致性。
4. 標準九幀 walk 執行：

```bash
python3 tools/validate_world_strip.py \
  --native-seed assets-source/role/<kind>/<id>/<variant>/seed_down_native_64.png \
  --strip assets-source/role/<kind>/<id>/<variant>/walk_down_strip_alpha.png
```

5. validator 通過不代表美術通過；仍須逐幀檢查臉、髮際、衣服層、左右腳、近遠腿、配件側、palette 與 root-lock。
6. 產生原生速度 GIF／影片供循環檢查，但保留 raw、Alpha、逐幀與 montage 作正式驗收證據。

## 八、W6：實景與 runtime QA

每方向至少提供一張靜態實景與一段移動預覽，使用實際 runtime frame、scale、camera 與 filter：

- 原生 `1×` 仍看得出方向、身份、服裝大色塊與腳步；角色不比地圖／NPC異常銳利或高彩。
- Player、Follower、NPC 同框比較頭部量、Pixel Art 密度、腳底、影子與 YSort。
- 實際 `1.8×` camera zoom 移動時檢查 pixel 不均、subpixel shimmer、滑步、方向切換與 follower 對齊。
- Nearest、lossless、mipmaps off；不得用 per-character scale 修補素材尺寸。
- 碰撞、互動範圍、出入口、YSort origin 與世界座標不因換圖改變。
- 影子由 runtime 獨立生成，沒有烘入 PNG；寬度、中心與淡出符合規格。

## 九、W7：正式整合

John 對 W6 明確回覆核可後才可：

1. 將 D1／D2／D3、raw／Alpha strip、逐幀、montage 與 review 存入 `assets-source/role/<kind>/<id>/overworld_<variant>_final/`。
2. 依規格命名與尺寸寫入 runtime `godot-project/assets/char/`；不得保留 per-character scale 修補。
3. 新增／更新 `world_art_meta.json`，版本鏈與 `mirror_safe` 依規格 §七。
4. 更新 `CREDITS_素材授權.md`、必要的任務進度與內容文件，執行 Reimport。
5. 跑 Godot headless、world smoke／harness；在編輯器實機跑目標場景確認無 error／warning。
