# 世界立繪流程（walk 素材的產出與整合）

- 版本: v1.10（2026-07-28；整合路德／亞倫四向 64px 簡易版 runtime）
- 驗收: 一律走 CLAUDE.md「產圖驗收流程」兩階段——**先預覽給 John 驗收，過了才整合**

---

## 一、產法

### 1. 先定世界地圖 style seed

不要直接把戰鬥 seed 縮小成 walk。先挑一張實際會使用的地圖截圖，連同角色外觀 reference 產出一張 `Down Idle` 世界角色候選，並合成回同一張地圖預覽。此候選通過下列檢查才可作為該角色的 walk seed：

- 色彩、飽和度、對比與頂光符合 [地圖畫面規格 §四](../design/地圖畫面規格.md#四、色彩規則)，沒有比地圖物件更刺眼的高彩度區塊。
- 描邊、陰影與細節密度不顯得比地圖／附近 NPC 更銳利或更像戰鬥立繪；必要時先調整深棕描邊、披風主色與金屬高光。
- 比例、腳底落點與視角放回實機截圖後自然；不得只在透明背景上驗收。

John 核可這張合成預覽後，才產生四方向 walk。角色外觀以這個世界 style seed 為準；同一地區的其他主角與新 NPC 都沿用相同地圖色盤與光影規則。

### 2. 產生與驗收步態

正式版：核可世界 style seed → 一次產完整方向 strip → 先驗 walk 四向步態再收尾。步態相位與一致性規則見 [design 規格 §四](../design/世界立繪規格.md)。

簡易驗證版：先只產四方向 Idle 並通過角色身份、方向、比例、色盤與 bottom-center anchor gate；再逐方向產 `Idle / Step L / Step R`。產圖 prompt 必須逐字標示兩張的前腳，並把 `Step L` 與 `Step R` 並排檢查。**任一方向無法清楚判讀左右腳交換，即退回重產，不得切圖、複製成 runtime 的 1..8 幀或請 John 以「大致可以」驗收。**

## 二、去背

同 [battle_art/prompts/sections/50_去背螢光底.md](battle_art/prompts/sections/50_去背螢光底.md)（螢光底＋沿輪廓深描邊）；每格 bottom-center 錨點正規化見 [battle_art/workflow.md](battle_art/workflow.md) Step 7。LPC 匯出本就透明。

去背不能只抽查四角 alpha 或只靠肉眼看縮圖。每次 resize、palette quantization、indexed／RGBA 轉換後，都必須對**最後交付尺寸的每一格**執行逐 pixel 檢查：

- `alpha > 0` 的 pixel 不得殘留螢光綠鍵色；符合綠色占優勢的殘點數必須為 `0`。
- `alpha = 0` 的 pixel，其 RGB 必須正規化為 `(0, 0, 0)`，避免隱藏鍵色在縮放、GIF 或後續轉檔時重新滲出。
- 同時以中性淺灰與高對比底色放大至少 6× 檢視輪廓；任一格計數不為 `0`，不得送預覽、保存 seed 或整合 runtime。

## 三、交付與命名

- 切圖：`assets/char/<id>_<Dir>_0..8.png`。
- 程式：`world_scene.gd` `_build_char_frames()` 組 `SpriteFrames`，動畫名 `Walk<Dir>`／`Idle<Dir>`（`<Dir>`＝Down/Up/Left/Right）。
- 像素圖 `.import` 用 **Nearest**。
- 整合後更新 `CREDITS_素材授權.md`。
- **簡易驗證版例外**：每方向可只產 Idle＋`Step L`／`Step R` 兩張步態；為相容現有 8 格 runtime，固定依 `Step L / Step R / Step L / Step R / Step L / Step R / Step L / Step R` 複製到 1..8。只用於比例、手感與地圖相容性驗證，不取代正式 8 相位 walk 規格。

## 四、預覽驗收清單

預覽階段一律只交候選圖，不整合素材；逐項勾完才請 John 看：

- [ ] 地圖合成預覽：角色放進目標地圖後，色調、飽和度、對比、描邊與頂光一致。
- [ ] 四方向 Idle：角色外觀、比例、腳底 anchor 與無劍設定一致。
- [ ] 側向標籤：`Left` 的鼻尖／腳尖必須朝畫面左，`Right` 必須朝畫面右；不得只依產圖 slot 或 prompt 順序命名。
- [ ] 四組 `Step L ↔ Step R` 並排檢查：每一方向都能直接辨認左、右腳互換；正面與背面不可兩格同腳在前。
- [ ] 正面 `Down` 解剖標記：角色的左腳位於畫面右側、右腳位於畫面左側；`Step L`＝畫面右腳向前，`Step R`＝畫面左腳向前。必須同時交換鞋尖落點、膝蓋重疊、褲管明暗與髖部遮擋，不能只看檔名。
- [ ] 側向步態以近腿亮、遠腿暗固定解剖身份；`Step L ↔ Step R` 必須交換前伸腿的明暗與髖部遮擋層級，不能只有相同輪廓平移。
- [ ] 角色中心與腳底 root-lock；衣物、髮型、披風與配件無缺層或跨格。
- [ ] 色調一致：三格放在同一中性底並排，逐材質比對頭髮、膚色、圍巾、皮甲與靴子的代表色；平均 luma 差異大於 5 時直接退回校色，低於 5 仍須通過肉眼材質色票檢查。
- [ ] 去背 0-residue gate：逐格掃描最終尺寸，確認 `visible chroma pixel = 0` 且透明區 `RGB residue = 0`；只檢查四角 alpha 不算通過。
- [ ] 若為簡易版，複製前先確認 1..8 的序列為 `L/R` 交替；若為正式版，確認 8→1 無縫。
